# telegramspeedreader — правила работы

Telegram mini app для скорочтения (RSVP) загружаемых книг. Владелец — Даниил Тынчеров.

- Продакшн: https://cybertatar.github.io/telegramspeedreader/ — публикуется сам при каждом
  пуше в `main` (`.github/workflows/deploy.yml`, нужен Settings → Pages → Source: GitHub Actions).
- Бот — Cloudflare Worker `worker/`, публикуется `.github/workflows/worker.yml` при пуше в `main`
  (секреты и переменные — в README, «Запуск бота»). Всё бесплатно: своего сервера и базы нет.
- Превью для согласования: артефакт https://claude.ai/artifact/9eJrQhbpdfwXaSYdkoPk7t (видит только владелец).

## Как работаем

1. Изменения делаем в отдельной ветке, `main` не трогаем.
2. Перед пушем в `app/`: `npm test`, `npm run build` (включает `tsc`) и `npm run format:check`
   без ошибок; в `worker/`: `npm test` и `npm run typecheck`.
3. Показываем результат в превью-артефакте: `npm run build:preview` собирает один HTML в
   `app/dist-preview/`; из него убрать обёртку документа и скрипт telegram.org (артефакт
   принимает скрипты только с CDN) и опубликовать по тому же URL. `alert`/`confirm` в превью
   не работают — подтверждения делаем в интерфейсе.
4. Сливаем в `main` только после явного «ок» владельца.
5. В конце сессии обновляем раздел «Статус» ниже.

## Устройство

- `app/` — мини-апп: Vite + TypeScript + Preact.
- Формат книги — `src/book/types.ts`: главы → блоки (`p`, `h`, `figure`, `code`, `table`).
  Любой формат приводится к нему.
- Движок — `src/engine/`: `stream.ts` превращает книгу в поток (слова + стоп-карточки,
  веса слов, паузы на знаках, страницы, размещение рисунка по первой ссылке в главе),
  `player.ts` — таймер с откатом после паузы и разгоном, `orp.ts` — опорная буква.
- Интерфейс — `src/ui/`. Главный экран — `Reader.tsx`: шапка с главой и страницей, слово в
  верхней трети (`.stage-zone`, владелец: внизу смотреть неудобно), под ним текст на паузе
  (`Context`), внизу зона для пальца (`.pad`), прогресс, скорость, оглавление и настройки.
  Держать палец можно и на слове, и в нижней зоне. Новое основное касание всегда начинает жест
  заново, а сворачивание и потеря захвата сбрасывают его: отпускание пальца может не дойти
  (перехватил Telegram или система), и раньше чтение «умирало» до перезахода в книгу.
- Telegram на телефонах открывается во весь экран (`requestFullscreen` в `telegram.ts`, атрибут
  `data-fullscreen`): сверху остаются кнопки Telegram «Закрыть» и «⋯», шапка читалки стоит в их
  полосе между ними (`--head-h`, `--head-side`); отступы — из `--tg-safe-area-inset-*` и
  `--tg-content-safe-area-inset-*`. На компьютере полный экран не включаем.
- Обложка EPUB в поток не попадает (иначе чтение начиналось с карточки «Иллюстрация»), заголовок
  главы, набранный обычным абзацем, второй раз не читается. Проверено на книге владельца —
  Понасенков, «Первая научная история войны 1812 года» (EPUB, 12 МБ, 407 тыс. слов, 186 иллюстраций).
- Разбор книг — в браузере, сервера нет: `src/book/import.ts` (TXT, FB2), `epub.ts` (fflate +
  DOMParser, главы из nav/toc.ncx), `pdf/` (pdf.js грузится лениво: `extract.ts` — текст с
  координатами и рамки графики, `layout.ts` — чистые функции раскладки: строки, колонки,
  колонтитулы, абзацы, код по одинаковой ширине символов, формулы, рисунки; `index.ts` — вырезки
  картинками). Подписи «Рис. N» / «Таблица N» / «Листинг N» забирает `captions.ts`.
- Раскладку PDF отлаживать на настоящих книгах: `extractPdf` работает в Node с
  `pdfjs-dist/legacy`, `layoutPdf` — чистая функция (дамп в JSON, затем вывод блоков текстом).
  Проверено на Pro Git (рус., 541 стр.) и статьях arXiv 1706.03762, 1512.03385.
- Хранение: настройки и прогресс — localStorage, книги — IndexedDB (`src/store.ts`). В Telegram
  список книг (`b_<file_unique_id>`) и прогресс (`p_<id>`) дублируются в CloudStorage; id книги из
  чата — `file_unique_id`. `PARSER_VERSION` поднимать при изменениях разбора: место в книге с
  другой версией восстанавливается по доле прочитанного.
- Связь с ботом — `src/cloud.ts` (`VITE_API_URL` при сборке); запросы подписаны initData,
  Worker проверяет подпись (`worker/src/auth.ts`).
- Обновления: Telegram на телефоне держит мини-апп в кэше (GitHub Pages отдаёт `max-age=600`, а
  WebView хранит и дольше). Сборка кладёт `version.json` с номером сборки (`GITHUB_SHA`),
  `src/update.ts` при запуске и возврате в приложение сверяет его и перезагружается с `?v=<сборка>`.
- Библиотека — книжная полка (`Library.tsx`, `Cover.tsx`): сверху «Читаю сейчас» (последняя открытая
  недочитанная), ниже сетка обложек с прогрессом; долгое нажатие — действия (удалить). Обложки:
  EPUB — `cover-image` / `<meta name="cover">`, FB2 — `coverpage`, PDF — первая страница; уменьшаются
  до 360px (`book/cover.ts`) и лежат в IndexedDB отдельно (`cover:<id>`), чтобы полка не грузила
  книги. Без обложки — сгенерированная: автор, название, черта на цвете из палитры по хешу названия.
  Название PDF без метаданных — самая крупная строка первой страницы (`titleGuess`).
- Тексты интерфейса — на русском.

## Бот и README

- Имя бота — «Vermis librorum (speed reader)» (`BOT_NAME`, выбрал владелец). Тексты бота
  (имя до 64 символов, описание до 512, короткое до 120, приветствие) — константы в
  `worker/src/index.ts`, выставляются ссылкой `/setup`; после их правки владелец открывает её снова.
- Аватарку и картинку описания API бота менять не умеет — только @BotFather. Рисуются из
  `tools/brand/*.html` скриптом `node tools/brand/render.mjs` в `docs/brand/` (аватарка 1024×1024,
  всё важное в круге; описание 640×360). Аватарка — книжный червь как таблица из анатомического
  атласа XIX века (гравюра, акварель, разрез «Sect. A—A», выноски, «VERMIS · LIBRORUM»); выбрана
  владельцем. Отклонены: просто слово с опорной буквой (скучно), сова (банально), милый
  мультяшный червячок, бусины-буквы; черновики — `tools/brand/concepts/`.
- Скриншоты README — `docs/screenshots/` (390×844 @2x, встроенная книга, Pro Git, статья
  «Attention Is All You Need»).
